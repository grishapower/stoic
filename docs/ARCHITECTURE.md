# Архитектура прототипа

## Слои

```
src/
  data/narration/        script.json — единственный источник текста (письмо + авторские реплики), типы, доступ к манифесту
  data/generated/        манифесты, которые пишут скрипты: voice-manifest.json, models.json, textures.json
  game/
    world/               чистые данные и функции мира: планировка, маршрут (сплайн), рельеф, полы, коллизии, растительность
    scenes/              R3F-компоненты сцены: небо и свет, рельеф, море, вилла, сад, территория, растительность, трава, пропсы
    characters/          Сенека: контроллер поведения (чистая логика) + визуал (GLB со скелетом или процедурный запасной)
    narrative/           последовательность прогулки и режиссёр повествования
    player/              ходьба от первого лица, коллизии, шаги, скамья
    audio/               Web Audio: голос (позиционный), процедурная атмосфера, музыка, шаги
    input/               клавиатура/мышь, pointer lock
    store.ts             zustand: фазы, оверлеи, субтитры, настройки (редко меняющееся состояние)
    runtime.ts           мутабельное покадровое состояние (позиции) — вне React
    session.ts           команды UI (начать, пауза, завершить…) — то, что требует жеста пользователя
    GameLoop.tsx         единый покадровый оркестратор
  components/ui/         невидимый UI: титул, субтитры, меню, письмо, размышление, журнал, финал
scripts/                 конвейеры ассетов: voice/, meshy/, assets/
```

## Покадровый порядок

`GameLoop` (useFrame с приоритетом −1, до рендера):

1. ввод → `updatePlayer` (мышь, WASD, коллизии, высота пола, покачивание камеры, шаги);
2. `updateDirector` — режиссёр повествования;
3. `updateSeneca` — поведение NPC;
4. шаги Сенеки, слушатель Web Audio по камере, позиция источника голоса = голова Сенеки.

Визуальные компоненты (`Seneca.tsx`, небо, вода, листва) читают состояние в своих `useFrame` и ничего не решают.

## Повествование отделено от анимации

`narrative/sequence.ts` — прогулка как декларативный список шагов: `phase`, `mode`, `music`, `allow` (Сенеке разрешено идти до станции), `arrive` (ждать прихода), `pause` (естественная тишина), `line` (реплика).

`narrative/director.ts` исполняет его и синхронизирует пять вещей:

| Что | Как |
|---|---|
| Текущий фрагмент | шаг `line`; следующая реплика стартует только после `postPause` и только если игрок ближе 8,5 м |
| Аудио | `audio.voice.play/pause/resume/stop`, события `onCue`/`onEnded` из манифеста |
| Субтитры | `onCue` → `store.narration.cueText` |
| Положение NPC | `seneca.allowance` (докуда можно идти) + `seneca.desiredSpeed` = оставшийся путь / оставшееся время речи участка (0,42–0,92 м/с), поэтому Сенека приходит к станции к концу блока |
| Состояние игрока | дистанция: ожидание (> 7,5 м Сенека останавливается и поворачивается), автопауза чтения (> 17 м), возобновление с начала прерванной фразы (+ «Так вот…», если пауза была долгой); пробел — пауза чтения; меню — заморозка |

Блоки письма привязаны к участкам маршрута: сад → кипарисовая аллея (1), аллея (2), оливковая роща → смотровая площадка (3), пергола → терраса (4), терраса (5).

## Сенека

`characters/senecaController.ts` — состояния `idle / greeting / walking / waiting / contemplating`, комбинируемые с «говорит». Он:
- никогда не убегает: замедляется с 5 м, стоит с 7,5 м;
- останавливается, если игрок стоит прямо перед ним;
- поворачивается плавно, с ограничением угловой скорости;
- голова и шея следят за целью (игрок, дорожка, море, свиток, деревья, стол) с периодическими взглядами на собеседника;
- жесты задаются огибающими.

`characters/Seneca.tsx` — визуал GLB:
- `AnimationMixer` смешивает idle / walk_thoughtful по скорости (timeScale по реальной скорости шага);
- talk-клипы стоя;
- во время ходьбы поверх неё идёт верхняя половина talk-клипа (треки ног отфильтрованы);
- одноразовые shrug / look_around;
- голова доворачивается процедурно в мировом пространстве, независимо от осей костей.

Если модель не загрузится, ErrorBoundary подставит `ProceduralSeneca`.

## Мир

Все системы стоят на одной земле, потому что высота задаётся аналитической функцией `world/terrain.ts`: её используют меш рельефа, игрок, Сенека и расстановка растительности.

Маршрут — центростремительный Catmull-Rom через `ROUTE`, параметризованный по длине дуги (`world/path.ts`). Коллизии двумерные: окружности и капсулы плюс полигон усадьбы, который не даёт уйти с обрыва.

## Свет и атмосфера

- Небо по модели Preetham с облаками (three r186 `Sky`).
- Солнце медленно опускается по ходу письма с 7,5° до 2,2°, после письма — ещё ниже. IBL перегенерируется через PMREM каждые 0,5° изменения высоты.
- Тень следует за игроком с привязкой к текселям.
- Направленный туман: к солнцу тёплый, от солнца сиреневый, поэтому горизонт сходится с небом.
- Листва и трава получают подсветку на просвет.
- Пост-обработки нет, кроме CSS-виньетки.

## Звук

См. [audio/engine.md](audio/engine.md). Голос — HRTF-панорама с 15–20 % неподвижной «присутственной» составляющей, чтобы письмо не терялось. Атмосфера, музыка и шаги синтезируются в коде.

## Производительность

Все числа по качеству собраны в `scenes/quality.ts` (плотности расстановки — рядом с ней: `world/flowers.ts`, `world/scatter.ts` → `SCATTER_SCALE`, `life/config.ts`).

- **Растительность:** инстансинг; деревья вокруг камеры — в полной детализации, остальные — дешёвым LOD в ячейках 300 м с отсечением по камере и тени (`Vegetation.tsx`, `geom/instances.ts`, `lod.ts`); набор пересчитывается раз на метр движения, без аллокаций.
- **Трава, цветы, скалы прибоя, рельеф** разбиты на чанки 3×3: у каждого своя bounding sphere, отсекаются по отдельности (раньше один инстанс-меш на всё поместье не отсекался никогда).
- **Плоды:** модель вблизи, дальше — простая сфера цвета кожуры без тени.
- **GLB-пропсы и мелкий декор** скрываются по дистанции, тени — по размеру предмета (`propLod.ts`); статичная кладка сведена в один меш на материал (`staticBatch.tsx`, `staticGeometry.ts`); дым и осциллы — одним вызовом.
- **Порядок отрисовки:** небо и море после земли (ранний отказ по глубине); шейдер рельефа не читает слои, которых в точке нет.
- **Тени и окружение:** на «Низком» карта 1024, полуширина 22 м, обновление через кадр; IBL пересобирается каждые 2,5° высоты солнца (на «Высоком» — 0,5°).
- meshopt + WebP для GLB, текстуры 1k. Потеря WebGL-контекста отслеживается, после восстановления канвас пересоздаётся.

**Замеры** (Mac, Retina, DPR 1.6; 2026-10-19):

| Станция | Десктоп «Высокое»: calls / треугольники | VR «Низкое», на глаз: calls / треугольники |
|---|---|---|
| сад | 359 / 3,8 M | 132 / 673k |
| аллея | 325 / 3,1 M | 108 / 560k |
| оливковая роща | 290 / 2,8 M | 119 / 596k |
| пергола-кабинет | 295 / 3,3 M | 150 / 776k |
| терраса | 213 / 2,1 M | 99 / 625k |

Десктоп держит 60 FPS на всех станциях (упор в частоту монитора). Бюджет для автономного Quest 3: ≤ 150 вызовов и ≤ ~0,9 M треугольников на глаз — соблюдён. Multiview (оба глаза за проход) в `WebGLRenderer` three r186 нет — только в `WebGPURenderer`, который не поддерживает патчи `onBeforeCompile`, на которых построены материалы (см. комментарий в `App.tsx`).

Не проверено на железе: стоимость пикселя на Quest 3 (MSAA 4×, alpha-to-coverage листвы, PBR), ~250–300 вызовов на два глаза для CPU, рывок компиляции шейдеров при первом виде. Возможный следующий шаг — упрощённые офлайн-версии GLB (8–15k → 2–4k треугольников).

## Взаимодействие и VR: плоды цитрусов

Некоторые деревья — мандариновые:
- четыре в клумбах перистиля (дотянуться можно с дорожки вокруг фонтана);
- сад у перголы;
- два деревца в кадках на портике.

Плоды можно сорвать, держать в руке, рассмотреть и отпустить. Отпущенный плод падает и катится по рельефу, его можно поднять снова. Если подойти к Сенеке с плодом в руке, он один раз за прогулку произносит авторскую реплику.

Код разделён так, чтобы VR-версия заменила только адаптер ввода и визуал руки:

| Слой | Файл | Зависит от устройства? |
|---|---|---|
| Данные: деревья, кроны, точки плодов | `world/citrus.ts` | нет |
| Состояние и физика плодов (`tree / held / falling / ground`), выбор лучом | `interaction/fruits.ts` | нет |
| «Рука»: прицел, схватить, отпустить с броском, рассмотреть | `interaction/hand.ts` (вход — `HandInput`) | нет |
| Десктоп-адаптер: луч из центра камеры, E / Q / R, скорость руки | `GameLoop.tsx` | да |
| Рука и плод от первого лица (привязаны к камере) | `player/HeldItem.tsx` | да |
| Рендер плодов одним `InstancedMesh` | `scenes/Fruits.tsx` | нет |

В VR работают те же `fruits.ts` (состояния и физика) и общий `hand` (его читают режиссёр и подсветка), но рук две и брать можно ладонью, см. ниже.

**Историческая оговорка.** Мандарины появились в Европе только в XIX веке. Исторически достоверный цитрус римского сада I века — цитрон (*Citrus medica*), он изображён на помпейских фресках. Переключение одной константой: `FRUIT_KIND = 'citron'` в `world/citrus.ts`. Подписи и размер плода подстроятся сами.

## WebXR (VR)

Без `@react-three/xr`: three.js `WebXRManager` + собственный тонкий слой в `src/game/xr/`. R3F сам переключает цикл кадров на XR при старте сессии.

| Слой | Файл | Что делает |
|---|---|---|
| Состояние | `xr/xrState.ts` | две руки (`left/right`): тип (контроллер / трекинг руки), точка хвата, ориентация, луч, хват с гистерезисом и фронтами, select, стик, кнопки, скорость, вибро; поза головы |
| Ввод | `xr/xrInput.ts` | читает группы three (`getController/Grip/Hand`, они дети рига). Контроллер: squeeze → хват, trigger → select, стик (оси 2/3), A/X, B/Y. Рука: хват = max(кулак, щипок), select = щипок; точка хвата — между большим и указательным пальцами или в согнутых пальцах |
| Игрок | `xr/xrPlayer.ts` | риг = начало пространства `local-floor`. Левый стик ведёт риг по направлению взгляда, правый — поворот вокруг головы: плавный (до 90°/с, скорость по наклону стика, мягкий разгон) или рывками по 30° (`settings.vrTurn`); при плавном повороте тоже включается виньетка. Голова — это тело: коллизии, высота земли (сглаженно), скамья-экседра. Публикует `runtime.player.pos/eye/yaw`, так что режиссёр, Сенека и звук работают без изменений |
| Плоды | `xr/xrHands.ts` | ближний хват ладонью (≤ 7,5 см от плода); дальний — по лучу, плод прилетает в руку за 0,22 с; разжать — бросок со скоростью руки. По плоду в каждой руке. Заполняет общий `hand` (подсветка, реплика Сенеки) |
| Сцена | `xr/XRSupport.tsx` | риг, слоты контроллеров, старт и конец сессии (камера уходит в риг и обратно, плод из десктопной руки падает), руки: модель `hand-fp` на контроллере; при трекинге — скиннинг-рука `generic-hand` (WebXR Input Profiles, MIT) через `XRHandModelFactory`, пока она грузится — суставы и кости из `InstancedMesh`; луч |
| Интерфейс | `xr/XRHud.tsx` | DOM в шлеме не виден. Карточка субтитров и подсказок (холст → текстура) лениво следует за взглядом; вопрос «На что я трачу своё время?» и финал — панели, кнопки которых нажимаются лучом (курок или щипок) |
| Сессия | `xr/xrSession.ts` | `detectXR` (кнопки в UI), `enterVR` из клика (жест обязателен), `local-floor` с откатом на `local`; на автономном шлеме или «Низком» качестве — масштаб буфера 0,9, максимальная фиксированная фовеация, 72 Гц; `beginWalkVR`, `resumeInVR`, `exitVR` |
| Эмулятор | `xr/emulate.ts` | `?xr=emulate` в dev ставит IWER (Quest 3) поверх `navigator.xr` |

В `GameLoop` ветка `xr.presenting` заменяет десктопный ввод (`updatePlayer` + адаптер руки) на `updateXRInput → updateXRPlayer → updateFruits → updateXRHands`, A/X ставит в очередь «взаимодействие» (`input.queueInteract`), B/Y — пауза чтения. Слушатель звука берёт мировую позу камеры. Фаза `title` в VR закрывает сессию. Десктопная рука (`HeldItem`) в VR скрыта, держимые плоды рисует `Fruits.tsx` (`fruitView.showHeld`).

Тесты: `src/__tests__/xr.test.ts` — хват рядом и лучом, следование за рукой, бросок, две руки, заморозка меню, потеря руки, распознавание щипка и кулака.

HTTPS для Quest в локальной сети: `npm run dev:vr` (режим `vr` в `vite.config.ts` подключает `@vitejs/plugin-basic-ssl`).

## Тесты

`npm test` (vitest) проверяет:
- целостность данных: полный текст письма, совпадение `tts` и субтитров, манифест и файлы озвучки;
- проходимость маршрута и коллизии;
- headless-прогон всей прогулки с поддельным аудиоплеером: письмо звучит целиком и по порядку, Сенека ждёт отставшего игрока, чтение ставится на паузу и возобновляется, меню замораживает сцену, реплика про плод звучит один раз и не ломает чтение;
- плоды: деревья стоят вне маршрута, плоды висят на досягаемой высоте и достаются с дорожки у фонтана, выбор лучом, цикл «сорвать → держать → бросить → лежит на земле → поднять».
